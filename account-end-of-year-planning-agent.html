ABOUT THIS AGENT

What it does

Runs as an MCP over DataHub and Snowflake and is used in Claude through the plugins MCP. It draws on the segmentation work already shared with the TVPs, including vertical industry classification and propensity to buy, so planning starts from the same numbers as the operating model.

How it works

1A seller or planner asks for an account plan in Claude, in plain language.
2Claude calls the MCP through the plugins connector.
3The MCP reads account data from Snowflake and the definitions behind it from DataHub.
4It applies the FY26 account hierarchies, industry vertical, and propensity-to-buy scores.
5Claude drafts the end-of-year plan, and the planner reviews it before it is used.

THE OUTPUT

What a plan looks like

A plan is read by the account team who act on it, by executives who allocate against it, and by analytics who check the model behind it. They all read the same plan. What makes that work is that every number carries where it came from and whether it has been signed off.

Every number names its source

A plan says which segmentation input each figure came from, so a reader can look it up in the semantic layer below.

Tied back to the operating model

The plan states where it matches the segmentation already shared with the TVPs, and where it has moved since.

Uncertainty is spelled out

Inputs still in validation are listed with what changes in the plan if they move on sign-off.

What a plan contains

Starting positionCurrent ARR, open pipeline, renewal date, and propensity to buy.
What it is built onEvery segmentation input used, its value for this account, and who owns it.
Tie-outWhere the plan matches the segmentation pack shared with the TVPs, and where it differs.
PrioritiesThe plays for the rest of the year, each naming the inputs it rests on.
What would changeWhich priorities move if an input still in validation changes on sign-off.
How it was builtDefinitions read from DataHub, model versions, what changed since the last run, and the analytics sign-off.
